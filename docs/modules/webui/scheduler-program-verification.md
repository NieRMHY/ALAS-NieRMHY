# 自定义调度隔离验收记录

验收日期：2026-09-29。范围为真实配置类、卡片解释器、`alas.py` 任务包装器与调度主循环、SQLite、真实 WebSocket 接口，以及浏览器 mock 编辑交互。没有启动真实模拟器或执行账号任务。

## 验收方法

`tests/test_scheduler_live_loop.py` 使用临时实例与 SQLite，运行真实 `AzurLaneConfig`、`AzurLaneAutoScript.get_next_task/run/loop`。替换设备、游戏任务方法、通知、备份与看门狗启动；虚拟时间驱动等待。禁止真实设备初始化，意外进入生产退避路径立即结束测试，避免异常被无限重试掩盖。

接口验收通过 Starlette TestClient 连接 `/api/v1/ws`，依次认证、读取目录、校验、保存、模拟、应用与查询状态；关闭连接后由真实调度宿主加载数据库并选出任务。读取与模拟过程没有创建 worker 或连接设备。

## 发现与修复

- 配置缓存重载后未重新接入调度运行时，维护恢复请求可能误写回普通任务队列。加载配置时立即重新绑定运行时。
- 启动跳过 Restart 的旧规则会吞掉自定义调度明确请求的恢复任务。仅原调度保留首次跳过规则。
- 原计划组合使用固定优先级，且原队列首位的系统任务可能遮住业务候选。组合改为读取原计划卡片，适配层只读取业务候选及业务等待时间。
- API 模拟按任务输入顺序选择原计划候选，与真实优先级不一致。模拟复用现有优先级合并与过滤规则。
- 资源确认未在页面不可见时清空上帧候选，可能接受不连续的可见帧。页面不可见时重置候选读数。

已有草稿中的组合是文档自身的一部分；不会静默覆盖用户编辑。需要更新默认示例时，先导出自己的方案，再点击「载入原调度方案」。后端修复需要重新启动 WebUI 或对应调度进程后生效。
