# 项目模块文档规范（docs/modules/ 撰写规范）

本规范统一 docs/modules/ 下所有模块设计文档的写法。目标：开发者**不通读源码**即可理解模块的定位、流程、依赖、配置、异常与修改注意事项。

每篇文档必须能回答五个问题：

1. 这个模块为什么存在？
2. 代码从哪里进入？
3. 核心流程怎么走？
4. 它依赖谁、谁依赖它？
5. 我要改它，需要特别注意什么？

---

## 1. 文件组织与命名

- 文档统一放 `docs/modules/`，目录与源码模块结构对应；大模块建目录 + `index.md`。
- 文件名全小写、`-` 分隔（如 `directory-map.md`）；单文档模块用平铺文件（如 `config.md`），多文档模块用目录。
- 不要按单个源码文件机械生成文档；**一个独立职责对应一篇文档**。

## 2. 标准结构（20 节）

标注「如不存在可省略」的小节，不存在就整节省略，绝不填充无意义内容。省略时**保留规范编号**（如省略第 9 节，则直接从第 10 节继续），不重排。

```markdown
# <分配的标题>

> 一句话描述模块。

## 1. 模块概述
定位、存在原因、解决什么问题、在系统中的位置；2-5 段。

## 2. 模块职责
### 负责
- ...
### 不负责
- ...   ← 必写，防止职责膨胀

## 3. 模块位置
目录树 + 文件作用表；不要贴目录树而不解释。

## 4. 核心入口
外部代码如何进入本模块（主入口/初始化入口/外部调用入口/回调入口）。
入口表：| 入口 | 用途 |。回答「追代码从哪开始看」。

## 5. 核心组件
最重要的类/组件/数据结构；重要字段用表格（| 字段 | 类型 | 说明 |）。

## 6. 工作流程
完整运行流程；复杂模块用 mermaid flowchart 表达逻辑，不要为图而图。

## 7. 调用关系
### 上游
| 模块 | 关系 |
### 下游
| 模块 | 用途 |

## 8. 数据流
数据从哪产生、在哪转换、流向哪；缩进箭头文本即可。

## 9. 状态模型
有明显状态才写；mermaid stateDiagram-v2 + 状态含义表。

## 10. 配置
| 配置 | 类型 | 默认值 | 说明 |
配置路径格式 <Task>.<Group>.<Argument>，代码访问 self.config.Group_Argument。
说明关键配置之间的关联。

## 11. 异常与错误处理
| 异常 | 原因 | 处理 |
说明哪些自动恢复、哪些终止、哪些上抛。

## 12. 并发与线程模型
存在线程/进程/事件循环/锁/队列/WebSocket 时必写：谁创建、谁拥有、
哪些对象线程安全、生命周期如何结束。

## 13. 缓存与持久化
内存缓存/JSON/YAML/文件缓存：存哪、何时读写、何时失效。

## 14. 生命周期
创建 → 初始化 → 运行 → 销毁；延迟初始化与退出释放。

## 15. 扩展方式
如何加功能；有注册器或固定流程必须写清步骤。

## 16. 修改注意事项
项目「隐形规则」：不能轻易改的地方及原因。

## 17. 已知限制
不隐藏技术债。

## 18. 示例
复杂模块给最小示例，只展示核心路径，不复制生产代码。

## 19. 调试方法
调试入口、常见日志、遇到问题先查什么。

## 20. 相关模块
链接同体系其他文档（相对路径），只链真实存在的文件。
```

## 3. 等级标准

- **S（核心模块）**：小节尽量齐全，约 250–500 行。
- **A（普通业务模块）**：至少覆盖 概述/职责/位置/核心入口/核心组件/工作流程/调用关系/配置/异常/修改注意事项，约 120–250 行。
- **B（简单模块）**：概述/职责/位置/核心入口/工作流程/修改注意事项（有配置或异常时补对应节），约 40–100 行。

篇幅以信息完整为准，不凑行数。B 级合并多篇模块时，每个子模块用 `###` 小节独立说明。

## 4. 写作原则（强制）

- **写设计，不要翻译源码**：禁止罗列「X 调用了 Y，Y 调用了 Z」式调用链；解释为什么这样设计、拆分解决了什么问题。
- **强调为什么**：如「TaskState 同时被调度器与 WebUI 线程访问，因此写操作必须经过锁」。
- **不写显而易见的信息**：不写 getX 获取名字；写稳定接口、被多处依赖的标识、隐含约束。
- **禁止行号与文件行数**（会迅速过时）；数量表述用「约」「截至 2026-09」。
- **禁止编造**：无法从源码确认的事实要么省略，要么在报告的 openQuestions 中说明，绝不臆写。
- 表格优先于大段文字；mermaid 只用于表达逻辑，语法必须有效。
- 全文简体中文；代码标识符（类名、方法名、路径、配置键）保持英文。
- 源码永远是对的：任务提示中的行为描述可能过时，一切以你实际读到的当前源码为准。

## 5. 格式细节

- H1 使用分配的标题；H1 下一行是 `>` 引用格式的一句话描述。
- 目录树 + 文件作用表成对出现，不要贴目录树而不解释。
- 代码示例只展示核心路径，不复制生产代码。
- 「相关模块」只链同体系内真实存在的文档（见下方文档地图），相对路径按实际层级（同级 `api.md`、下级 `os/index.md`、上级 `../base/index.md`）。
- 不写 YAML frontmatter（这是参考文档，不是 cursor rule）。
