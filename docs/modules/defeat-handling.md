# 战败与结果记账

> 统一 C/D 失败画面、单场心情事件与任务恢复，避免结算处理器互相吞掉状态。

## 1. 模块概述

评价、舰队是否仍可使用、任务如何恢复是三个问题。C/D 使用同一红色 DEFEAT 画面；失败后当前舰队可能仍可使用，也可能因前排或后排全部沉没而由游戏自动切换。脚本不能把“没有弹窗”或“自律正在运行”当作本场胜利。

普通任务用非 S 结果的额外 10 点保护舰队最低心情估计。牺牲编队任务具有显式豁免，仍复用同一套结果识别。它们不应通过复制执行循环绕开记账。

## 2. 模块职责

负责确认结果、每场记账去重、区分弹窗正文，以及执行既有撤退/换队策略。

不负责从单张评价图推算各舰船剩余血量、从 A 评价推断具体沉船数，或替代真实模拟器验收。

## 3. 模块位置

```text
module/combat/result.py          # 单场上下文
module/combat/combat.py          # 公共识别、点击与心情事件
module/combat/auto_search_combat.py  # 自律寻敌恢复
module/handler/info_handler.py   # 排除无可用舰队弹窗的委托误识别
module/raid/                    # 正常共斗与沉船政策
module/coalition/               # 多轮联盟与沉船政策
```

`CombatResult` 保存结果；`Combat` 负责记录与调用恢复钩子；`AutoSearchCombat` 才决定主线地图上的撤退或换队。活动派生类只声明差异。

## 4. 核心入口

| 入口 | 用途 |
| --- | --- |
| `combat_result_reset()` | 在普通战斗或自动搜索战斗入口重置本场状态 |
| `combat_result_record()` | 记录等级/确定战败，最多额外扣减一次并调用恢复钩子 |
| `handle_combat_defeat()` | 处理 C/D 共用红色失败画面 |
| `combat_result_observe()` | 自动搜索或联盟只观察结果，不点击 |
| `auto_search_combat_status()` | 关闭弹窗、推进结算并执行地图恢复 |
| `Emotion.check_fleet()` | 恢复自律前检查实际接替舰队的下一场基础消耗，不等待或扣减 |

## 5. 核心组件

| `CombatResult` 字段 | 含义 |
| --- | --- |
| `fleet_index` | 本场画面舰队编号，决定心情账本与换队目标 |
| `emotion_reduce` | 是否允许本场额外心情记账；与联盟基础消耗开关分开 |
| `rank` | 已识别的评价；未知保持 `None` |
| `defeated` | 已通过共用失败画面或无可用舰队正文确认战败 |
| `fleet_unavailable` | 本场已识别无可用舰队正文，确认战败队前排或后排失效 |
| `shipwreck_reduced` | 本场是否已调用额外扣减，防止重复画面重复扣减 |
| `affection_recorded` | 本地主线/活动图是否已处理本场明确成功结果的好感事件 |

## 6. 工作流程

1. 战斗入口创建新上下文；确认进入战斗后按任务规则扣基础心情。
2. S/A/B 由现有评价或经验区域识别。C/D 字母颜色只作为进入结算的信号，动画误匹配不能直接确认失败。
3. 红色 DEFEAT 画面统一调用 `handle_combat_defeat()`，先记录，再按冷却点击关闭。沿用的资源名称 `OPTS_INFO_D` 不表示只有 D 使用它。
4. 若出现无可用舰队正文，同时记录战败与 `fleet_unavailable`，点击专用确认后继续截图等待游戏自动切换。正文模板避开动态舰队名称；这里的失效指前排或后排无可用角色，不要求六艘全部沉没。
5. 没有该弹窗时，当前队可能仍可使用但严重受损，三种策略均直接撤退。游戏会按道中/Boss 职责重新选择可用舰队，手动换队后开自律可能再次派出原战败队。
6. 游戏战败时已停止自律，撤退全程不点击自律开关，回到选关页才算完成。仅 `switch_fleet` 同时满足本场失效证据、当前画面已自动换至另一队及接替队心情预检通过时，才允许恢复自律；不点击手动切换或舰队撤离按钮。
7. 恢复前保存已确认的画面舰队编号，下一场据此记账。若开启后立即进入加载/战斗，也按正向状态结束恢复；转场暂时读不到编号时保留上次确认，不回退为默认一队。

## 7. 调用关系

主线、活动、三油和紧急委托经 `CampaignBase` 使用公共结果层。正常共斗经 `RaidCombat` 使用普通战斗入口；联盟每个内部战斗经自动搜索执行入口建立自己的结果上下文，再由活动循环推进下一轮。

`RaidScuttleCombat` 和 `CoalitionScuttleCombat` 豁免额外心情。联盟通过 `auto_search_defeat_recovery=False` 自行推进活动，不执行主线地图撤退策略。

## 8. 数据流

```text
新截图 → 正向结果识别 → CombatResult → 可选额外心情扣减
                                      → 首次确定战败 → 任务恢复钩子
心情扣减 → Emotion.reduce() → Value / Record / RecoveryState 原子保存
```

## 9. 状态模型

`defeated`、`fleet_unavailable` 和 `shipwreck_reduced` 在一场内只从假变真。重复失败画面、评价页和经验页共用同一状态，下一场才重置。前一场的失效证据不能授权下一场继续换队。

自动搜索的 `_withdraw` 表示恢复待处理。失效证据来自本场弹窗，接替队来自当前截图的 `FLEET_NUM_1/2`；曾经看到另一队、自律运行或确认按钮均不能单独授权开启。移除跨场的“还有其他舰队”标志，等待自动换队超时则回退撤退。

## 10. 配置与任务政策

| 场景 | 基础消耗 | 非 S / 确定战败额外消耗 | 后续流程 |
| --- | --- | --- | --- |
| 主线/活动/三油/紧急委托 | 每场 2，双倍书 4 | 每场最多 10 | 自律寻敌按 `Campaign.DefeatWithdraw` |
| 正常共斗 | 每场 2，双倍书 4 | 每场最多 10 | 共斗结果与任务循环 |
| 共斗沉船 | 每场基础消耗 | 豁免 | 原沉船任务循环 |
| 正常联盟多队 | 整关一次基础消耗 | 每个内部战斗最多 10 | 活动自行进入下一轮 |
| 正常联盟单队 | 每个内部战斗扣基础消耗 | 每个内部战斗最多 10 | 活动自行进入下一轮 |
| 连战刷好感（本地三队） | 第 1/2 队各一次基础消耗，第 3 队不记账 | 全部豁免 | 受益队明确 S/A/B 各加一次好感，牺牲队不加；保留 `SCUTTLE_CONFIRM`，SP 需明确 S 且未战败才按成功收尾 |

`Emotion.Mode=ignore` 完全不记心情；`calculate` 和 `calculate_ignore` 正常记账。`Emotion.IgnoreShipwreck` 仅豁免额外 10 点，公共心情沿用同一套事件。

主线/活动图在明确 S/A/B 结果时累计一次好感，基础扣减不再把尚未结束的战斗计为胜利。连战刷好感复用公共执行和重新入场，每场独立重置结果与好感标记，1/2 队各自计数，3 队仅推进沉船流程；手操武器门控和 `Fleet2Mode` 保留。正常/连战任务均不能凭自律运行或结算超时补造 S。连战/共斗在无视心情模式下保留好感计数，门槛使用手动配置值且不要求恢复相位。共斗刷好感保持按出击累计；`triggered_normal_end` 只负责登记下一轮石油复核，明确战败后清除，下一场结果重置前不提前丢失信号。

S 不额外扣减；A 包含慢速胜利，无法从等级区分是否沉船，默认也扣 10。此处是保守估计，不表示游戏对所有舰船都扣了 10。未知等级不假定 S，也不凭未识别画面制造扣减事件。

`Campaign.DefeatWithdraw` 三种策略：

- `withdraw_continue`：每次战败撤退后继续任务。
- `withdraw_stop`：每次战败撤退，连续三次后确认退出关卡，再禁用当前任务。
- `switch_fleet`：本场已识别失效弹窗、游戏自动换到另一队且心情预检通过后恢复；无弹窗或自动换队超时则撤退。

## 11. 异常与错误处理

正常撤退抛 `CampaignEnd`；三次连续战败停止抛 `ScriptEnd`。未知画面仍由既有 `GameStuckError` / `GameTooManyClickError` 保护，不能因为结算超时就盲点失败按钮或编造战败。

接替舰队可能原本处于待命，地图入口的预检会跳过它。恢复前 `Emotion.check_fleet()` 按实际画面编号检查下一场基础消耗；独立模式使用对应舰队账本，公共模式使用共享账本，忽略模式跳过。心情不足沿用任务延迟，不可用账本沿用 `RequestHumanTakeover`，调用方先退出地图再上抛原异常；旧配置的可信数值可由本地 `get_recovered()` 兼容入口重建未知相位，不能绕过预检或等下一场开始后才检查。

## 13. 缓存与持久化

单场结果只在当前任务实例内保存，不写入用户配置。基础与额外扣减通过现有 `Emotion` 账本持久化，不另建恢复模型；不使用真实用户配置做回归测试。

## 14. 生命周期

`combat()` 或 `auto_search_combat_execute()` 重置结果，执行与结算阶段持续补充正向证据，任务恢复结束后由下一场重置。联盟多轮不能把第一场的去重标记沿用到后续战斗。

## 15. 扩展方式

新任务复用公共入口；额外消耗豁免覆写 `combat_shipwreck_emotion`，联盟基础消耗覆写 `coalition_emotion_reduce()`，专用确认通过 `coalition_result_confirm_buttons` 声明。新增结果布局需提供真实截图识别，不能把通用确认按钮当作等级。

## 16. 修改注意事项

- 委托与舰队失效弹窗共享蓝色「确定」位置，必须先识别正文。正文随动态舰队名居中偏移，检测扩大横向搜索，点击前清除正文偏移，使用固定确认按钮坐标。`handle_urgent_commission()` 对已知舰队失效正文返回 `False`，由战败流程操作。
- 换队按本场画面编号计算另一队，不能使用舰队顺序反转后的道中/Boss 角色编号。一队道中、二队道中均适用；确认接替队后更新 `fleet_show_index`，下一场基础和额外消耗都归实际出战队。
- 自律开关 ON/OFF 使用相同文字，关闭状态仍可命中 ON 模板。撤退路径不得用该模板点击所谓“关闭”，否则会开启自律；需要判断运行状态时沿用 `is_auto_search_running()` 的模板与颜色双重识别。
- 记录状态不带点击冷却；操作才带间隔。所有结果处理器 `True` 仍只表示已操作。
- 保留掉落记录的 7 秒评价点击窗口；移除固定休眠后用冷却控制点击节奏。

## 17. 已知限制

本次无可用舰队正文素材来自 CN 1280×720 原图；其他语言正文尚无对应截图验收。评价颜色、动画和共斗/联盟特殊布局仍需真实模拟器覆盖，离线回放不能证明账号中所有活动版本均已验收。

客户端 Lua 的 `BattleDataProxy` 评分逻辑区分超时与舰队失效，`LevelStageView.CheckFleetChange` 在队伍失效后先调用 `StopAutoFight(BATTLE_FAILED)`，再显示自动换队提示；`TryAutoFight` 通过 `GetFleetOfDuty` 按职责选择舰队，原队仍有效时可能切回原队。普通关卡 `FinishStageCommand` 使用沉船能量扣减。评分名称不作为恢复分支依据；服务端专属活动消耗不能仅凭客户端未出现某个调用证明。

## 18. 实机验收场景

| 场景 | 应观察到的结果 |
| --- | --- |
| C/D 战败，前排或后排全沉 | 正确关闭失败页与无可用舰队弹窗，没有“紧急委托”误日志 |
| 战败后撤退，包括游戏已自动换二队 | 自律开关点击次数为零；处理确认后直接撤退，不让二队出击 |
| C/D 战败，当前队仍可使用 | 三种策略均直接撤退，不点击切换或自律，不让受损当前队再战 |
| 游戏自动换到另一队，配置换队 | 本场已见失效弹窗，当前目标编号与心情预检通过后恢复，不点手动切换 |
| 二队道中、一队 Boss，以及相反顺序 | 两个方向均按实际画面编号换队与记账；加载转场不把二队记为一队 |
| 接替队未校准或心情不足 | 开启自律前先撤退，再人工接管或按恢复时间延迟 |
| 撤退停止连续三次 | 每次先退出地图，第三次再停止任务 |
| 普通 S/A/B 与重复经验页 | S 只有基础消耗；A/B 最多额外扣一次 10 |
| 正常/沉船共斗与联盟多轮 | 基础消耗次数正确；沉船任务无额外扣减，专用确认不丢失 |

## 19. 调试方法

运行 `uv run python -m unittest tests.test_auto_search_defeat tests.test_combat_results tests.test_emotion_recovery`。截图夹具调用正式识别器；虚拟时钟和符号帧覆盖状态流转、两种编队顺序、直接进入加载、失效证据重置及接替队预检。关闭自律的真实地图截图需验证 ON/OFF 模板同时命中，但运行状态为假，并在多帧恢复流程中断言撤退全程不点击任何自律开关。先查 `[战斗-结算] 已确认战败结算`、`[战斗-结算] 战败舰队已无法成型`、`[战败计数]`、点击按钮及心情基础/额外扣减日志，再核对恢复后的舰队编号与自律开关。
