# 舰船数据

「舰队管理 → 舰船数据」提供四个平级页面，顺序为舰队科技、养成计算、扫描更新、我的舰船。入口为 `/i/:instance/task/FleetAnalysis`，首次默认我的舰船，后续按实例记住上次页签；显式 `tab=data|technology|mind|scan` 链接优先。

各实例分别在浏览器保存搜索、筛选、等级区间、排序、显示开关和扫描范围，切换页签或刷新后恢复。编辑草稿仍按原有会话存储保存，不与显示偏好混合。页面不再每5秒重新读取数据；进入页面、重连和用户点击「重新载入」时读取，保存或审核操作直接使用返回的新数据。扫描结束后点击「重新载入」查看待确认更新。

隔离模拟数据的界面记录：[修改前](images/fleet-data-preferences-before.png)、[修改后桌面](images/fleet-data-preferences-desktop.png)、[修改后窄屏](images/fleet-data-preferences-mobile.png)。修改前按上游 `dev` 的页面源码复现；修改后桌面展示已选中的去重、搜索和等级筛选，截图不含真实账号数据。

重构目标与验收清单见 [固定重构计划](fleet-data-refactor-plan.md)。

四个页面共用主程序的字体、主题颜色、面板圆角及表单样式。正文、筛选与表格统一13px，辅助说明12px，分区标题15px，汇总数值24px；页面主标题沿用全局样式。完成记录保留绿色、满级待觉醒保留橙色，表格列、筛选项、编辑行为及内部独立滚动不因样式调整而改变。

## 数据原则

正式账号数据分为当前舰船与累计科技。当前舰船逐卡存储，同名副本保留独立 ID；累计科技按舰船种类保存获取、满星、120 级里程碑，状态仅为已完成、未完成，未记录项目默认未完成。删除当前舰船不删除累计科技。图鉴提供身份、形态、阵营、舰种与奖励规则。

扫描、文件导入和截图识别只生成待确认更新。统计读取已确认数据；页面浏览和养成计算不会启动游戏任务或改写正式数据。

## 我的舰船

首次加载等待舰船数据和图鉴全部就绪后，一次显示完整筛选表与明细；等待期间统一展示加载状态，避免舰种和阵营后补导致筛选框两段展开。

表格第一列展示与舰队科技相同的图鉴编号，默认按编号升序，点击编号表头切换升降序；无编号显示—并始终置后，同名副本及改造沿用所属舰船编号。其余列展示名称、副本、等级、突破状态、舰种、阵营、稀有度及核对状态；舰名、等级、突破状态和核对标记可直接原地修改。搜索、筛选与表格使用舰队科技相同的蓝色表头、分区筛选按钮、隔行底色及搜索结果数量。筛选支持类别、稀有度、阵营及等级区间；完成情况仅保留未满级、未满星、已满星、120级及以上，记录筛选提供需核对、重复舰船、等级未知和突破状态未知。同组多选取并集、跨组取交集，不提供加成筛选。全量表格不分页，表头固定、内部独立滚动。数量区分舰船艘数与种类数。核对状态只显示正常、待核对或等级未知。满星状态在突破状态列单独展示。名称、等级、突破状态、舰种、阵营、稀有度、核对状态均可点击表头切换升降序并显示方向，排序覆盖筛选后的全部记录，切换排序或筛选时表格回到顶部，未知值始终置后；阵营按图鉴顺序、稀有度按实际等级排序。不再提供独立排序下拉框。

取消逐条查看／编辑入口与详情侧栏。选择舰名时自动更新身份、舰种、阵营和稀有度；身份不确定时保留待核对。未确认身份的行可操作核对框：唯一规范化名称可直接确认；同名多身份在舰名下选择阵营、舰种和编号对应的候选，不猜测身份；没有候选时提示先修正舰名。确认候选只修改当前副本草稿，点击顶部「保存」后生效。新增行固定在列表前方，删除先标记为待删除并允许恢复；新增、删除、批量标记和各行修改均由顶部唯一的「保存」按钮一次提交。`?tab=data&ship=ID` 定位并高亮对应副本。

记录筛选新增「去重后舰船」：在其他筛选结果内按舰船组保留最高等级副本，同等级优先改造形态，再按副本 ID 稳定选择。不同身份的同名舰不会合并；未确认身份的每条记录单独保留。该按钮可与其他记录条件组合，只有显示效果，不删除或合并数据库记录。显式副本链接优先显示并高亮指定副本，避免记住的筛选或去重隐藏定位目标；浏览偏好保持原值。

满星状态在新增、保存修改和确认扫描／导入时强制写入：所有已知等级低于70级的舰船为未满星；身份确认的常规舰船100级及以上为已满星，规则优先于手工值。70–99级不触发阈值规则；科研、META、原生UR不以高等级判定满星。其余保留已知状态，否则为未知。0级表示等级未知，不按低等级处理。舰船报告对旧记录按同一规则显示默认状态，读取不会回写数据库或重算累计科技；实际保存时才写入该副本的新状态。当前副本未满星不会清除历史累计满星科技。

编辑草稿保存在当前浏览器会话，关闭和切换页面后仍可恢复。保存检查捕获的数据版本；数据已更新时，需要丢弃旧草稿并重新核对。筛选和排序不清空草稿；编辑时维持已保存记录的位置，避免输入中行消失或跳动。删除在统一保存后生效，累计科技保留。

## 舰队科技

列表参照 [Wiki「舰队科技列表」](https://wiki.biligame.com/blhx/舰队科技#舰队科技列表)：一种有科技奖励的舰船一行，双层表头分为编号、名称、阵营／分组、舰种、科技点（获得／满星／Lv.120／合计）、属性加成（解锁／120级）。科技点列展示各阶段可得点数，用 ✓／— 区分已完成／未完成；获得、满星、120级的数字格分别随自身完成状态标绿；120级完成时编号、名称、阵营和舰种标绿，三个里程碑全部完成才将合计格标绿。已解锁的属性单元格仍单独标绿。另设「满级待觉醒」手动标记列，玩家在编辑模式下点击切换并统一保存；选中仅该格标橙，提供同名筛选及排序。该标记默认关闭，独立于三个科技里程碑，不影响科技点、加成或全部完成判定，不与里程碑联动，也不由数据初始化或合并推算。SQLite 中该字段为非空布尔值。当前持有不再占一列，舰名链接跳转对应舰船，悬停显示当前副本数量与最高等级。

表头可排序，全量列表不分页，支持浏览器查找。筛选提供前排／后排和舰种、七档稀有度、阵营、加成舰种、加成属性、完成情况；额外筛选可分别指定解锁及120级加成。组内多选取并集，不同筛选组取交集；舰种和属性必须匹配同一奖励阶段。无科技奖励的舰船不混入此表。

舰队科技和养成计算均提供「未练满级」筛选，范围为Lv.120记录未完成且未标记「满级待觉醒」的舰船，不要求已获得。科技表另设「每千心智科技点」列，与养成页共用科技点公式及完整100→120级心智费用规则，固定两位小数；点击表头首次降序、再次升序，缺失值置后。该指标不受里程碑完成情况和当前等级影响。

打开「记录编辑模式」后，直接点击获得、满星、Lv.120的数字格或解锁、120级加成格切换状态，不弹出选择框。获得和解锁共用获取记录，Lv.120和120级加成共用120级记录。点亮满星时补记已获得；点亮120级时补记已获得，常规舰船还补记满星。取消获得或解锁会同时清除满星和120级；常规舰船取消满星时同时清除120级，特殊舰船仅清除满星；取消120级保留获得和满星；关联格子的高亮、科技点、属性加成和合计随草稿同步更新。所有修改和阵营等级通过统一「保存」提交，点数及属性总加成预览随草稿更新；切换页面后仍保留本实例浏览器会话草稿。数据版本变化不覆盖旧草稿。无需逐舰打开纠错面板。

里程碑独立保存在 `technology_progress`，后续新增、改级、删除、船坞扫描或舰船导入确认均不自动修改它。新数据库首次确认舰船数据时可以用正向事实初始化一次；先手工维护科技记录则跳过自动初始化。JSON 导入在进入待确认表前将旧记录转换为新版里程碑，不在日常读取时推算。未持有不等于未获取。

「合并舰船数据」仅在点击时取当前已确认舰船的正向事实，与保存的里程碑作并集：只补入已完成状态，保留全部原有已完成状态；数据中未知和未完成的状态不会删除历史进度。保存中的未提交修改须先保存或放弃；操作检查科技及数据版本，重复合并无新增时不更新版本。未核对舰船不作为依据。手动修改可以独立纠正任一里程碑，不因数据现状拒绝或自动恢复；自动补记仅在点亮操作时进行，取消获得时联动清除满星和120级，常规舰船取消满星同时清除120级；取消120级不反向清除前置记录。保存提交该行三个最终状态，重新载入时不恢复被取消的状态。

满星推算仅用于数据自身的强制状态、首次初始化及显式并集，不能统一将所有超过100级的舰船视作满星。科技全部完成要求三个里程碑都确认完成。

## 养成计算

首次加载等待舰船、科技记录、图鉴及养成费用结果全部就绪后，一次显示完整页面，避免先显示筛选和空费用表再补入计算结果。后续计算保留已有页面并提示正在计算，结果返回后更新。舰船报告复用入口已加载的数据，静态图鉴只在首次加载、重连或失败后主动重试时获取；手动重新载入舰船报告后同步读取科技记录，与舰船数据版本对齐后计算，不定时轮询。

自动读取当前舰船和累计科技：每个有科技奖励的舰种取现有最高等级的一艘，目标固定为120级。已完成累计120级科技或现有最高等级已到120级的舰种不重复计算，退役后保留的累计完成记录同样有效。身份待核对和无科技奖励舰种不参加自动选择。累计120级里程碑未完成的舰种按当前等级计算费用。

页面展示心智单元、物资及逐舰明细，另提供每千心智科技点：120级奖励科技点除以按基础稀有度计算的100→120级完整心智单元费用，再乘以1000。分母固定包含100、105、110、115四次觉醒，科研PR按SSR、DR按UR，不采用当前剩余费用，浏览器排除偏好不改变该指标。数值固定保留两位小数，排序使用原始精度。舰船、当前等级、心智单元、物资、每千心智科技点五列可点击表头切换升降序，首次默认按每千心智科技点从高到低，后续恢复上次排序，缺失值始终置后。暂不计算经验。范围和结果使用已加载的确认数据，无需从科技页加入或先手动选船。版本冲突保留原有重新载入恢复机制。

筛选表与舰队科技一致，支持类别、稀有度、阵营、加成舰种、加成属性，以及分别指定解锁和120级加成的额外筛选；同组多选取并集、跨组取交集。完成情况仅保留未练满级、未满星、满级待觉醒；养成范围只包含当前持有舰船，不提供未获得、已获得及范围内冗余的未满级、Lv.120和未完成选项。状态筛选读取同一份已保存科技记录；「满级待觉醒」列共享科技页的手动标记，选中标橙，在科技页编辑保存后同步显示。搜索支持舰名、图鉴别名及编号。搜索与筛选只影响显示明细，不改变参与计算范围和资源合计。

按实际等级固定计算：100、105、110、115级都视为未支付下一阶段觉醒费用，包含该边界及后续阶段的剩余费用；超过边界才跳过该笔费用。移除假设等级、已觉醒上限和觉醒待确认提示，接口只接受已确认副本和目标等级。仅保留可选的按舰种排除及「恢复全部参与」，排除在最高等级副本变化后继续有效，不改写舰船和科技事实。页面使用与舰队科技一致的配色及表格样式，全量明细内部独立滚动，异常原因显示在舰名下并链接到数据核对。

计算排除偏好按实例保存在浏览器 `localStorage`，按舰种记录，不存入舰船数据库。费用规则离线保存于 `assets/ship/cultivation.json`，由 `dev_tools/fleet_cultivation_extract.py` 提取并记录来源和 SHA256。

## 扫描更新

页面按开始读取、读取进度、确认更新组织。游戏扫描可设等级范围；文件支持 JSON/CSV/XLSX，截图支持 PNG/JPEG/WebP。导入与截图保留同名副本，不先做最高等级合并。旧 JSON 导入收在折叠项。

当前游戏扫描读取舰船身份、等级等可识别字段，不读取额外经验和满星状态。未读取字段不能覆盖已有人工值。实时阶段依赖调度状态，最近一次成功读取摘要记录来源、时间、读取数量、待核对数量和完整性；它与正式舰船数量分开展示。正常扫描只派生完整性和核对数量，不生成旧的群组历史记录。扫描异常详情仍查看运行日志，不以未读到记录推断成功或退役。

无歧义新增和更新可批量确认；移除单独确认，同名对应不明确时选择具体副本或明确新增。只有满足完整扫描条件才产生缺失移除建议。未处理的结果阻止下一次扫描或导入，避免覆盖。

## 存储与接口

每个实例使用 `config/fleet/<实例名>.sqlite3`，当前 schema v11。`ships` 保存逐卡数据，`technology_progress` 保存独立里程碑及满级待觉醒标记，`nation_technology` 保存阵营等级；待确认差异独立存表，不保存逐副本历史证据。已删除旧 `technology` 表、`fleet_info.technology_fields` 以及旧人工等级／等级切换端点的存储。待导入科技只保存三个可选布尔里程碑，不保存旧格式副本。

仅保留 JSON → SQLite 转换入口：`fleet_legacy` 在显式导入时解析旧配置、处理旧人工记录并生成新版数据，玩家确认后写入正式表；原 JSON 保留。运行时不再读取旧科技表，也不再自动升级旧 SQLite schema；版本不符时明确报错，不重置或覆盖数据库。本次当前数据库的结构清理离线执行并先备份，不保留运行时升级分支。

获取、满星和120级里程碑均为非空布尔值，不另设“未核实”列。舰船数据 `ships.full_star` 仍为三态（`true` 已满星、`false` 未满星、`null` 未知）。一次性科技初始化标记继续保留，读取不重播数据推算。累计完成状态直接保存在 `technology_progress`，退役不清除；初始化和显式并集不再写入历史证据，报告及版本摘要也不包含历史证据。原始归档、备份及旧测试数据副本不作为运行配置自动加载。

| 接口 | 行为 |
| --- | --- |
| `dock.report` | 当前舰船、版本、待确认差异及最近读取摘要 |
| `dock.patch` | 按副本 ID 更新或移除；新增分配新 ID |
| `dock.stageImport` | 将解析后的文件/截图舰船暂存为待确认更新 |
| `dock.review` | 校验正式数据与候选版本，逐项确认或忽略 |
| `dock.configure` | 保存下一次扫描等级范围 |
| `dock.importLegacy` | 显式读取本实例旧 JSON 为待确认更新 |
| `fleetTech.report/patch` | 读取或独立编辑累计里程碑及阵营等级 |
| `fleetTech.mergeShips` | 显式将当前舰船正向里程碑与原进度作并集，仅增加完成状态 |
| `mind.plan` | 按数据版本、具体副本实际等级及固定边界规则只读计算 |
| `mind.catalog / fleetTech.catalog` | 公共舰船身份、科技和费用资料 |
| `mind.import/recognize` | 解析上传内容，不写入正式数据 |

当前接口只服务已确认舰船、累计科技、养成计算及待确认更新；旧清单、独立心智覆盖和同步接口已删除。`ships.extra_exp` 保留为可空非负整数，供后续使用；当前养成计算仅使用等级，不计算经验。旧计费排除标记已删除。

写操作继续使用登录、实例隔离、生命周期锁和版本校验。游戏扫描只在明确启动任务时执行；测试使用临时配置、数据库和离线截图，不操作真实游戏。
